# 用户故事与验收标准（User Stories & Acceptance Criteria）

> 校园二手交易平台 · 黎钟 · 2027 届软件工程
> 用途：把"功能清单"改写为**用户视角的需求**，并为每条用户故事给出可验证的验收标准（Acceptance Criteria），
> 同时关联到仓库中已有的自动化测试用例与缺陷编号，形成**需求 → 测试 → 缺陷**的可追溯链路。

## 0. 使用说明

| 项 | 约定 |
| --- | --- |
| 故事编号 | `US-模块-序号`，如 `US-GOODS-03` |
| 角色定义 | **游客**（未登录）、**用户**（已注册的学生）、**卖家**（发布商品的用户）、**买家**（下单的用户）、**管理员** |
| 优先级（MoSCoW） | **必须**（Must，MVP 闭环）、**应该**（Should，体验完整）、**可以**（Could，增强） |
| 验收标准格式 | `Given 前置条件 / When 操作 / Then 预期结果`，每条 AC 都必须可被测试验证 |
| 可追溯 | 每条故事标注对应的自动化测试编号与相关缺陷编号；无自动化覆盖的标注"手工" |

## 1. 用户与账号（US-USER）

### US-USER-01 注册账号 【必须】
**作为** 一名在校学生，**我希望** 用学号/用户名和密码注册账号，**以便** 开始使用平台买卖闲置物品。

**验收标准**
- AC1　Given 我填写的用户名未被占用、密码符合规则 / When 我提交注册 / Then 注册成功并自动登录，跳转到首页。
- AC2　Given 用户名已被占用 / When 我提交注册 / Then 提示"用户名已存在"，不创建账号。
- AC3　Given 两次输入的密码不一致或必填项为空 / When 我提交 / Then 前端拦截并提示，不发送请求。

**对应测试**：E2E 1.1、E2E 1.5　**相关缺陷**：无

### US-USER-02 登录与登录态保持 【必须】
**作为** 已注册用户，**我希望** 登录后在一段时间内保持登录状态，**以便** 不用每次操作都重新登录。

**验收标准**
- AC1　Given 我已注册 / When 我输入正确的用户名和密码 / Then 登录成功，token 被保存，页面显示我的昵称。
- AC2　Given 我输入错误的密码 / When 提交 / Then 提示"用户名或密码错误"，不清空已填用户名。
- AC3　Given 我未登录 / When 我访问需要登录的页面（如发布商品、我的收藏）/ Then 被路由守卫拦截并跳转到登录页。
- AC4　Given 我连续多次输错密码 / When 超过限流阈值 / Then 提示请求过于频繁（限流生效）。

**对应测试**：E2E 1.2、权限越权 2.1、部署验证 D17（登录限流）　**相关缺陷**：无

### US-USER-03 完善个人资料与上传头像 【应该】
**作为** 用户，**我希望** 修改昵称、联系方式并上传头像，**以便** 让交易对方更容易信任我。

**验收标准**
- AC1　Given 我已登录 / When 我上传一张合规头像并保存 / Then 头像立即更新并在顶栏显示。
- AC2　Given 我上传超过大小限制的图片 / When 提交 / Then 返回友好提示而非系统错误。
- AC3　Given 我未填写必填项 / When 保存 / Then 提示校验失败。

**对应测试**：E2E 1.3　**相关缺陷**：BUG-06（>5MB 图片提示不友好，已修复）

## 2. 商品发布与管理（US-GOODS）

### US-GOODS-01 发布商品 【必须】
**作为** 卖家，**我希望** 填写标题、价格、分类、描述并上传图片发布商品，**以便** 把闲置物品挂出来。

**验收标准**
- AC1　Given 我已登录且填写了完整信息、上传 1 张图片 / When 我提交 / Then 商品创建成功，
  状态为**在售**，并立即出现在首页商品列表（**已用真实浏览器实测确认**，见
  [用户故事视角测试报告](测试报告-用户故事视角.md) 的 US-GOODS-01 与 US-GOODS-01b）。
- AC2　Given 标题、价格或分类为空 / When 提交 / Then 前端提示，不发送请求。
- AC3　Given 价格填写非数字或负数 / When 提交 / Then 被校验拦截；售价输入框为
  `el-input-number`（`:min=0.01`、`:precision=2`），组件层先做一道约束，
  规则层（`utils/productRules.js`）再给出统一提示。

> **修订说明**：本条最初写作"创建后为待审核、前台不可见"，后经真实浏览器实测发现
> 当前版本的发布流程是**直接上架在售**，故按实测行为更正（详见上述测试报告）。

**对应测试**：E2E 1.4、1.4b　**相关缺陷**：无

### US-GOODS-02 商品卡片展示分类与编号 【应该】
**作为** 买家，**我希望** 在商品卡片上看到分类名称与分类编号，**以便** 快速判断商品类别。

**验收标准**
- AC1　Given 首页已加载 / When 我查看任意商品卡片 / Then 显示正确的分类名称与分类编号（如"专业课教材 · G4-012"）。
- AC2　Given 分类数据来自接口（扁平结构 + parentId）/ When 页面渲染 / Then 子分类正确继承一级分类的编号，不出现兜底编号 `ZZ`。

**对应测试**：单元测试 31 条（分类索引/编号规则）、E2E 1.5b　**相关缺陷**：BUG-16-01（分类索引解析错误，33 个分类全部错乱，已修复）

### US-GOODS-03 上架与下架自己的商品 【必须】
**作为** 卖家，**我希望** 对自己已通过审核的商品执行下架，**以便** 不想卖时及时撤下。

**验收标准**
- AC1　Given 我的商品处于"在售"状态 / When 我点击下架 / Then 商品变为"已下架"，首页列表不再显示。
- AC2　Given 商品属于**其他用户** / When 我尝试调用下架接口 / Then 返回 403/业务错误，商品状态不变（越权防护）。

**对应测试**：权限越权 2.2　**相关缺陷**：BUG-01（匿名可获取非上架商品，已修复）

### US-GOODS-04 查看商品详情 【必须】
**作为** 买家，**我希望** 点击卡片进入详情页查看完整信息，**以便** 决定是否联系卖家。

**验收标准**
- AC1　Given 商品处于"在售"状态 / When 我点击卡片 / Then 详情页正常渲染图片、价格、描述、卖家信息。
- AC2　Given 商品处于"待审核"状态且访问者不是卖家本人或管理员 / When 我直接访问详情 URL / Then 提示"商品不存在"或不可见（不泄漏未上架商品）。
- AC3　Given 我是卖家本人 / When 访问自己的待审核商品 / Then 可以看到详情（身份区分正确）。

**对应测试**：E2E 1.5b、权限越权 2.3　**相关缺陷**：BUG-02（待审核商品详情对任意访问者可见，已修复）

## 3. 审核与后台管理（US-ADMIN）

### US-ADMIN-01 管理员审核商品 【必须】
**作为** 管理员，**我希望** 对"待审核"商品执行通过或驳回，**以便** 保证平台内容合规。

**验收标准**
- AC1　Given 存在待审核商品 / When 管理员点击"通过" / Then 商品状态变为"在售"，立即出现在首页列表。
- AC2　Given 存在待审核商品 / When 管理员点击"驳回" / Then 商品不上架，卖家侧可见驳回状态。
- AC3　Given 我是普通用户 / When 我访问后台审核页面或接口 / Then 被拦截（后台路由守卫 + 接口权限校验双层）。

**对应测试**：后台 E2E（e2e-v013-admin.py）、E2E 1.4b　**相关缺陷**：无

### US-ADMIN-02 强制下架违规商品 【应该】
**作为** 管理员，**我希望** 强制下架违规商品，**以便** 及时阻断不合规内容。

**验收标准**
- AC1　Given 某商品在售 / When 管理员强制下架 / Then 商品变为已下架，买家侧不再可见。
- AC2　Given 强制下架完成 / When 我查看操作记录 / Then 能看到该操作（可追溯）。

**对应测试**：后台 E2E　**相关缺陷**：无

### US-ADMIN-03 用户启用/禁用 【可以】
**作为** 管理员，**我希望** 禁用违规用户，**以便** 维护平台秩序。

**验收标准**
- AC1　Given 某用户存在 / When 管理员禁用该用户 / Then 该用户登录后无法进行发布等写操作。

**对应测试**：后台 E2E　**相关缺陷**：无

### US-ADMIN-04 数据看板 【应该】
**作为** 管理员，**我希望** 在后台看到核心运营数据（概览、7 天趋势、分类与状态分布），**以便** 了解平台运行情况。

**验收标准**
- AC1　Given 管理员已登录后台 / When 打开数据看板 / Then 图表正常渲染，无 JS 报错，数据与数据库一致。

**对应测试**：后台 E2E（页面 JS 错误 0）　**相关缺陷**：无

## 4. 检索与浏览（US-SEARCH）

### US-SEARCH-01 关键词搜索商品 【必须】
**作为** 买家，**我希望** 输入关键词搜索商品，**以便** 快速找到想要的物品。

**验收标准**
- AC1　Given 首页已加载 / When 我输入"教材"并搜索 / Then 列表只显示名称包含"教材"的**在售**商品，URL 同步变化。
- AC2　Given 搜索无结果 / When 提交 / Then 显示空状态提示（而非空白页）。
- AC3　Given 我执行搜索、切换分类、翻页 / When 每次操作 / Then 同一接口**只发送一次请求**（不重复请求）。

**对应测试**：E2E 1.5、异常场景 4.2　**相关缺陷**：BUG-03（搜索页重复请求，已修复）

### US-SEARCH-02 按分类筛选 【应该】
**作为** 买家，**我希望** 点击分类查看该类商品，**以便** 按类别浏览。

**验收标准**
- AC1　Given 首页已加载 / When 我点击某分类 / Then 只显示该分类（含子分类）的在售商品，分页正确。
- AC2　Given 分类下无商品 / When 进入 / Then 显示空状态。

**对应测试**：E2E 1.5、部署验证 D23　**相关缺陷**：无

### US-SEARCH-03 只看在售商品（数据隔离）【必须】
**作为** 访问者，**我希望** 列表与搜索只展示在售商品，**以便** 不看到无效信息。

**验收标准**
- AC1　Given 数据库中同时存在待审核、已下架、交易中、已售出商品 / When 我访问列表接口或搜索 / Then 只返回状态为"在售"的商品。
- AC2　Given 我匿名访问列表接口 / When 查看返回结果 / Then 不包含任何非在售商品（接口级过滤，而非前端过滤）。

**对应测试**：权限越权 2.4、部署验证 D24　**相关缺陷**：BUG-01（接口越权泄漏，已修复）

## 5. 收藏（US-FAV）

### US-FAV-01 收藏与取消收藏 【应该】
**作为** 买家，**我希望** 收藏感兴趣的商品，**以便** 之后回来查看。

**验收标准**
- AC1　Given 我已登录并打开某商品详情 / When 我点击收藏 / Then 按钮变为已收藏，收藏记录写入数据库。
- AC2　Given 我已收藏该商品 / When 再次点击 / Then 取消收藏，记录删除。
- AC3　Given 我在两个窗口同时点击收藏同一商品 / When 并发提交 / Then 一个成功、另一个返回业务提示"已收藏该商品"，数据库**收藏记录数恒为 1**（无脏数据）。

**对应测试**：E2E 1.6a~1.6c、异常场景 4.4　**相关缺陷**：BUG-04（并发返回技术性错误码，已修复）

### US-FAV-02 查看我的收藏 【应该】
**作为** 买家，**我希望** 在"我的收藏"中分页查看收藏列表，**以便** 集中管理。

**验收标准**
- AC1　Given 我有若干收藏 / When 我进入我的收藏 / Then 分页展示，可取消收藏。
- AC2　Given 我没有收藏 / When 进入 / Then 显示空状态。

**对应测试**：E2E 1.6b　**相关缺陷**：无

## 6. 站内私信（US-CHAT）

### US-CHAT-01 私聊卖家 【必须】
**作为** 买家，**我希望** 在商品详情页直接私聊卖家，**以便** 询问细节并协商。

**验收标准**
- AC1　Given 我已登录并打开他人商品详情 / When 我点击"私聊卖家"并发送消息 / Then 消息发送成功，卖家侧会话列表出现该会话。
- AC2　Given 卖家在线 / When 我发送消息 / Then 卖家**无需刷新**即可收到（WebSocket 推送）。
- AC3　Given 我打开自己的商品详情 / When 我尝试私聊自己 / Then 被拦截（不允许给自己发私信）。

**对应测试**：E2E 1.7a~1.7b、权限越权 2.6　**相关缺陷**：无

### US-CHAT-02 消息已读回执 【应该】
**作为** 买家，**我希望** 看到自己发出的消息是否已被对方阅读，**以便** 判断对方是否在线关注。

**验收标准**
- AC1　Given 我发送了消息 / When 对方打开会话（后端标记已读）/ Then 我的消息下方显示"已读"状态。
- AC2　Given 对方未打开会话 / When 我查看消息 / Then 显示"未读"。

**对应测试**：E2E 1.7c~1.7e　**相关缺陷**：BUG-16-02（已读回执链路齐全但模板从未渲染，已修复）

### US-CHAT-03 会话列表与未读数 【应该】
**作为** 用户，**我希望** 在消息页看到所有会话与未读数量，**以便** 优先处理待回复的消息。

**验收标准**
- AC1　Given 我有若干会话 / When 打开消息页 / Then 按最近消息时间排序，未读数准确。
- AC2　Given 我进入某会话 / When 返回列表 / Then 该会话未读数清零。

**对应测试**：E2E 1.7b、部署验证 D14~D16（WebSocket）　**相关缺陷**：无

## 7. 订单交易（US-ORDER）

### US-ORDER-01 买家下单 【必须】
**作为** 买家，**我希望** 对在售商品下单，**以便** 锁定该商品并进入交易流程。

**验收标准**
- AC1　Given 商品处于"在售"且我不该商品的卖家 / When 我点击下单并确认 / Then 订单创建成功，商品状态变为"交易中"。
- AC2　Given 商品已是"交易中"或"已售出" / When 我下单 / Then 提示商品不可购买，**不产生订单**（防一物多卖）。
- AC3　Given 两人同时对同一在售商品下单（并发）/ When 两个请求同时提交 / Then **只有一个成功**，数据库订单数 +1，商品状态唯一。
- AC4　Given 我是该商品的卖家 / When 我尝试购买自己的商品 / Then 被拦截。

**对应测试**：E2E 1.8、异常场景 4.5（并发抢购）、权限越权 2.5　**相关缺陷**：无

### US-ORDER-02 买卖双方订单视图 【必须】
**作为** 买家/卖家，**我希望** 分别看到"我买到的"和"我卖出的"订单，**以便** 管理自己的交易。

**验收标准**
- AC1　Given 我下单成功 / When 我打开"我买到的" / Then 能看到该订单及状态。
- AC2　Given 我的商品被别人下单 / When 我打开"我卖出的" / Then 能看到该订单及买家信息。
- AC3　Given 该订单与我无关（第三方）/ When 我尝试访问订单详情 / Then 被拒绝（越权防护）。

**对应测试**：E2E 1.9a~1.9b、权限越权 2.3　**相关缺陷**：无

### US-ORDER-03 确认交易完成 【必须】
**作为** 卖家，**我希望** 在完成线下交付后确认交易完成，**以便** 结束订单并标记商品已售出。

**验收标准**
- AC1　Given 订单处于"待交易" / When 卖家确认完成 / Then 订单变为"已完成"，商品变为"已售出"，买家侧同步可见。

**对应测试**：E2E 1.10a~1.10b　**相关缺陷**：无

### US-ORDER-04 取消订单并释放商品 【必须】
**作为** 买家或卖家，**我希望** 取消未完成的订单，**以便** 商品重新回到在售状态。

**验收标准**
- AC1　Given 订单处于"待交易" / When 我取消订单 / Then 订单变为"已取消"，**商品状态恢复为"在售"**，可被其他人购买。
- AC2　Given 订单已完成 / When 我尝试取消 / Then 不允许取消。

**对应测试**：E2E 1.11（含商品释放断言）　**相关缺陷**：无

## 8. 推荐与运营（US-RECO）

### US-RECO-01 首页个性化推荐 【可以】
**作为** 买家，**我希望** 首页看到"猜你喜欢"，**以便** 发现可能感兴趣的商品。

**验收标准**
- AC1　Given 我有浏览/收藏行为 / When 打开首页 / Then "猜你喜欢"返回与行为相关的商品（Item-CF + 内容召回 + 热门三路融合）。
- AC2　Given 我没有任何行为（新用户）/ When 打开首页 / Then 返回热门商品作为兜底，不报错。

**对应测试**：E2E 1.5、部署验证 D26　**相关缺陷**：无

### US-RECO-02 商品详情页相似商品 【可以】
**作为** 买家，**我希望** 在详情页看到相似商品，**以便** 对比后决策。

**验收标准**
- AC1　Given 我在某商品详情页 / When 页面加载 / Then 显示若干相似商品，点击可跳转。

**对应测试**：E2E 1.5b　**相关缺陷**：无

### US-RECO-03 举报违规商品 【可以】

## 9. 质量与非功能需求（US-QUALITY）

> 这一组是**跨功能的非功能需求**，也是本项目测试与质量工程的主要对象。

### US-QUALITY-01 接口权限与越权防护 【必须】
**作为** 平台方，**我希望** 任何写操作都必须校验身份与归属，**以便** 防止越权操作与信息泄漏。

**验收标准**
- AC1　Given 我未登录 / When 调用任何写接口 / Then 返回 401，操作不生效。
- AC2　Given 我登录为普通用户 / When 调用管理员接口 / Then 返回 403。
- AC3　Given 我登录为普通用户 / When 操作**他人**的订单/商品 / Then 被拒绝，数据不变。

**对应测试**：权限越权 6 条 + 部署验证 D10/D24　**相关缺陷**：BUG-01、BUG-02（均已修复）

### US-QUALITY-02 页面三态完备（加载/空/错误）【应该】
**作为** 用户，**我希望** 每个页面在加载中、无数据、请求失败时都有明确反馈，**以便** 不会面对空白页不知所措。

**验收标准**
- AC1　Given 数据正在请求 / When 页面打开 / Then 显示加载态（骨架屏或加载提示）。
- AC2　Given 请求返回空列表 / When 页面渲染 / Then 显示空状态文案与引导。
- AC3　Given 请求失败（如后端未启动）/ When 页面渲染 / Then 显示错误态与重试入口，**不是白屏**。
- AC4　Givne 全部页面 / When 运行 `tools/check-states.py` / Then 20 个页面全部达标、缺失数为 0。

**对应测试**：`tools/check-states.py`（CI 中运行）、部署验证 D3~D5　**相关缺陷**：BUG-16-05（非法模板组合与失效绑定，已修复）

### US-QUALITY-03 界面视觉一致（设计令牌）【可以】
**作为** 平台方，**我希望** 所有颜色、间距来自统一的设计令牌，**以便** 视觉一致且便于统一调整。

**验收标准**
- AC1　Given 前端全部源码 / When 运行 `tools/check-tokens.py` / Then 裸色值数量为 0（CI 中锁定为 0）。

**对应测试**：`tools/check-tokens.py`　**相关缺陷**：无

### US-QUALITY-04 可访问性与对比度 【应该】
**作为** 有视觉或操作障碍的用户，**我希望** 文字对比度达标、键盘可操作、图片有替代文本，**以便** 正常使用平台。

**验收标准**
- AC1　Given 全部页面 / When 运行 `tools/ui-a11y.py` / Then 对比度不达标项为 0（装饰性文字除外）、焦点可见、图片均有 alt。
- AC2　Given 我只用键盘 / When 浏览并操作主要流程 / Then 所有可点击元素均可到达并触发（无鼠标独占元素）。

**对应测试**：`tools/ui-a11y.py`、`tools/check-states.py`（鼠标独占 0）　**相关缺陷**：BUG-16-04（对比度回归 3 → 15 处，已修复）

### US-QUALITY-05 窄屏可用（手机浏览）【应该】
**作为** 用手机浏览的同学，**我希望** 页面在 390px 宽度下不出现横向溢出，**以便** 正常查看与操作。

**验收标准**
- AC1　Given 前台页面 / When 视口宽度为 390px / Then 无横向滚动条，核心操作可完成。
- AC2　（已知例外）管理后台侧栏固定宽度，窄屏会溢出；**经评估不做适配**，已记录在测试报告的遗留问题中。

**对应测试**：`tools/capture-ui.py` + 人工走查　**相关缺陷**：无

### US-QUALITY-06 热点数据缓存与限流 【应该】
**作为** 平台方，**我希望** 热点接口有缓存、高频接口有限流，**以便** 保证系统在高并发下可用。

**验收标准**
- AC1　Given 商品列表/详情/分类/推荐接口 / When 重复请求 / Then 命中缓存（Redis），响应时间显著下降。
- AC2　Given 缓存中不存在的数据被反复请求 / When 请求 / Then 空值缓存生效，不压垮数据库（防穿透）。
- AC3　Given 同一 IP 高频调用登录接口 / When 超过阈值 / Then 返回限流提示（本项目对**本机同样生效**，需专门测试）。

**对应测试**：部署验证 D12/D17/D18、压测脚本 load-test.py　**相关缺陷**：无

### US-QUALITY-07 缺陷可追溯与质量不退化 【必须】
**作为** 项目维护者，**我希望** 每个缺陷都有记录、每次改版都不让质量指标倒退，**以便** 长期维护。

**验收标准**
- AC1　Given 发现任何缺陷 / When 登记 / Then 记录发现方式、复现步骤、根因、修复与验证结果。
- AC2　Given 代码推送 / When CI 运行 / Then 三类静态检查与三套测试自动执行；指标超过阈值则失败（棘轮机制）。

**对应测试**：`.github/workflows/ci.yml`、`docs/defect-log.md`　**相关缺陷**：全部 12 条缺陷均按此流程闭环
