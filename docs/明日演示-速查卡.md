## ③ 3 分钟 · AI 开发经验（四个故事，各 40 秒）

| 故事 | 说什么（带数字） |
| --- | --- |
| **TDD** | 订单状态机先写 **41 条测试**，一跑**红 24 条** —— 其中两条是**我读错了需求**（以为"只能买家完成""不能一步完成"），是测试把我拉回文档 |
| **排障** | CI 连续 6 轮红、日志读不到；靠失败注解里的 **`exit 127`** 定位到：两个 job 缺 `working-directory: backend` |
| **对齐** | 写脚本抽出 **66 个业务错误码 + 12 个状态取值**，逐条问"用户故事里有吗"；又扫全仓文档抓出 **5 处真矛盾** |
| **纠错** | 我为跑测试**误删过两次真实数据**；此后把默认库改成测试库、加非基线数据保护、每次清库自动备份 → **AI 会犯错，关键是把错变成防线** |

## ④ 2 分钟 · 提问预案（一句话答）

| 问 | 答 |
| --- | --- |
| 数据量/并发？ | 演示 19 商品；Redis 缓存列表与详情、登录限流 20 次/分；瓶颈在 DB 写入，可读写分离 |
| 为什么不用 ES？ | 当前量级 MySQL 前缀/全文足够；是"可扩展点"不是必需 |
| 安全怎么保证？ | JWT + `@LoginRequired` 统一鉴权；**52 条**安全用例（匿名 401 / 越权 403 / 只能操作自己资源） |
| 机审准确率？ | 违禁词 + 可疑规则 + 联系方式正则三层，**保守设计**：可疑只转人工不直接拒 |
| 买家能跳过卖家吗？ | 不能（已修）：必须 卖家标记交付 → 卖家确认交付 → **买家**确认收货；越权返回 6004/6005 |
| AI 代码可信吗？ | 三条兜底：941 条用例、CI 覆盖率棘轮、我逐条核对业务规则与文档 |
| 下一步？ | 端到端进 CI、组件测试扩面、论文与中期材料 |
