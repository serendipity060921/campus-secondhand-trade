# 运维手册 · 数据库备份与恢复

> 校园二手交易平台 · v0.18 新增（C 阶段收尾）
> 脚本：`tools/backup-db.ps1`（主逻辑） + `tools/backup-db.bat`（启动器）

## 一、为什么需要这个

项目原本**只有"开发时的安全网"**：`tools/seed-demo-data.py` 在改动演示数据前会顺手
`mysqldump` 一份到 `db/demo-data/backup-<时间戳>.sql`。

那是给开发用的，有三个不足：**没有保留策略**（越攒越多）、**没有恢复验证**
（生成了文件但没证明能用）、**不适合挂计划任务**。生产环境需要的是：
定期自动备份 + 自动清理旧文件 + **确认备份真的能恢复**。

## 二、怎么用

```powershell
# ① 日常备份（挂计划任务用这个）
tools\backup-db.bat

# ② 备份 + 恢复演练（建议每周跑一次）
tools\backup-db.bat -Verify

# ③ 只看会做什么，不动任何数据
tools\backup-db.bat -DryRun

# ④ 自定义参数
tools\backup-db.bat -KeepDays 30 -OutDir D:\db-backup -Verify
```

> ⚠️ 为什么用 `.bat` 而不是直接跑 `.ps1`：Windows 默认执行策略是 Restricted，
> 直接双击/调度 `.ps1` 会报"在此系统上禁止运行脚本"。`.bat` 启动器用
> `-ExecutionPolicy Bypass` 调用脚本，**不需要改机器策略**。

参数一览：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-MysqlHome` | `D:\major\tool\mysql-8.4.4-winx64\bin` | MySQL bin 目录 |
| `-DbName` / `-DbHost` / `-DbPort` | `campus_trade` / `127.0.0.1` / `3306` | 目标库 |
| `-DbUser` / `-DbPassword` | `root` / `123456` | 连接凭证 |
| `-OutDir` | `<仓库>\db\backups` | 备份输出目录（已在 .gitignore 中） |
| `-KeepDays` | 14 | 普通备份保留天数 |
| `-KeepMonths` | 12 | 月度长期备份保留月数 |
| `-MinSizeKB` | 10 | 文件小于该值视为导出失败 |
| `-Verify` | 关 | 执行恢复演练 |
| `-DryRun` | 关 | 只打印动作 |

## 三、保留策略

- **普通备份**：`campus_trade_yyyyMMdd-HHmm.sql`，保留最近 **14 天**；
- **月度长期备份**：每月第一次运行时额外复制一份 `campus_trade_yyyyMM-monthly.sql`，
  保留 **12 个月**（用于"几个月前数据被误删"这类场景）。

清理只针对上述两类文件名，不会误删其他文件。

## 四、★ 恢复演练（这个脚本的核心价值）

`-Verify` 会做一次完整的"备份能不能用"的验证：

```
① 记录源库 7 张关键表（user / product / category / favorite / orders / message / moderation_log）的行数
② 创建临时库 campus_trade_restore_test_<时间戳>
③ 把刚导出的备份导入临时库
④ 逐表比对行数 —— 有任何一张表不一致即判定失败
⑤ 无论成功失败都删除临时库，不留垃圾
```

**实测结果（2026-10-16）**：

```
[INFO] 备份前关键表行数：user=9, product=24, category=33, favorite=6,
                        orders=6, message=13, moderation_log=11
[INFO] 导出完成：campus_trade_20261016-2057.sql（48 KB），已确认不含 CREATE DATABASE / USE
[INFO] 恢复演练通过：7 张关键表行数与源库一致
[INFO] 临时库已清理：campus_trade_restore_test_205701
[INFO] === 备份结束（成功）===
```

> 注：这里的行数是**表的物理行数**（含逻辑删除的测试数据），
> 与演示数据不变量断言（`4/17/4/4/9`，只统计 `deleted=0`）口径不同，两者不矛盾。

## 五、挂计划任务

```bat
REM 以管理员身份运行一次，建立每天 02:30 的备份任务
schtasks /Create /TN "CampusTrade-DB-Backup" /SC DAILY /ST 02:30 ^
  /TR "\"D:\campus-secondhand-trade\tools\backup-db.bat\"" /RL HIGHEST /F

REM 查看 / 立即运行 / 删除
schtasks /Query /TN "CampusTrade-DB-Backup" /V /FO LIST
schtasks /Run   /TN "CampusTrade-DB-Backup"
schtasks /Delete /TN "CampusTrade-DB-Backup" /F
```

日志写入 `deploy/windows/logs/backup-db.log`（脚本会同时输出到控制台）。

## 六、两个踩过的坑（都写进代码注释了）

1. **导出不能用 `--databases`**：那样 dump 里会带
   `CREATE DATABASE campus_trade` 和 `USE campus_trade`，
   恢复演练时会把临时库的导入**直接打到生产库上**。
   现改为把库名作为参数传入，并在导入前扫描 dump 内容 —— 一旦发现
   `CREATE DATABASE` / `USE` 就拒绝执行。
2. **`.ps1` 必须存成带 BOM 的 UTF-8**：Windows PowerShell 5.1 会按 GBK 读无 BOM 的文件，
   中文注释乱码后**破坏语法**（报"缺少右括号"之类的怪错）。用编辑器改动本脚本后，
   请确认文件开头是 `EF BB BF`。
   另外 `$PSScriptRoot` 在 `param()` 默认值里可能取不到，脚本已改为在函数体内解析。

还有一条：mysql 会把 `[Warning] Using a password...` 写到 **stderr**，
而脚本设了 `$ErrorActionPreference='Stop'` —— PS 5.1 会把原生命令的 stderr 当成错误中断。
脚本在调用 mysql 的函数里临时放宽该设置并过滤该警告。

## 七、灾难恢复的手工步骤

万一需要从备份恢复生产库：

```powershell
# ① 停后端（释放数据库连接）
Get-NetTCPConnection -LocalPort 8080 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

# ② 先备份当前状态（万一还要回退）
tools\backup-db.bat

# ③ 导入指定备份（注意：备份不含 CREATE DATABASE / USE，需显式指定库名）
cmd /c "D:\major\tool\mysql-8.4.4-winx64\bin\mysql.exe -h 127.0.0.1 -u root -p123456 ^
        --default-character-set=utf8mb4 campus_trade < db\backups\campus_trade_20261016-2057.sql"

# ④ 校验数据不变量
python tools\seed-demo-data.py --verify

# ⑤ 重启后端（注入 env.ps1 中的环境变量）
```

> 建议每学期至少**真的演练一次**第 ③④ 步 —— 备份没被恢复过，就不能算备份。
