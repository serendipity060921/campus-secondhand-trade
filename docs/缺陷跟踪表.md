## 四、这张表怎么用

**写进论文**：作为研究内容"AI 生成代码的质量风险及其拦截手段"的**实证材料**。
从本表可以归纳出一类规律 —— AI 辅助能显著加快实现层产出，但在以下几类问题上更容易遗漏，需要人工评审与自动化测试兜底：

1. **边界与后缀**类（BUG-001）：键/字段带变体时"漏删漏改"；
2. **异常分支覆盖不全**类（BUG-002）：只覆盖主流程，未覆盖协议层异常；
3. **安全配置与依赖**类（BUG-003）：功能正确但**暴露面**与**依赖版本**被忽略；
4. **契约一致性**类（BUG-004）：跨模块的编号/枚举等"无形约定"；
5. **工程门禁本身失效**类（BUG-005）：以为有 CI，实际没跑测试。

**答辩用途**：回答"你的测试到底有没有用" —— 本表每条都是测试先于修复发现的。

## 五、维护约定

- 新发现缺陷**追加新行**，编号递增；**不修改历史行**（保留发现与修复的原始记录）
- 修复后必须在"回归证据"列写明**可执行的验证方式**（用例编号 / 命令 / 断言点），保证可复现
- 修复提交的 commit message 中引用编号（如 `fix: 修正缓存漏删（BUG-001）`），便于双向追溯
