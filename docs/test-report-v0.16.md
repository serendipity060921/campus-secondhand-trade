## 一、测试范围与方法

### 1.1 测试分层

| 层级 | 用例数 | 方法 | 工具 |
| --- | ---: | --- | --- |
| 端到端（用户视角） | 31 | 两个独立浏览器上下文分别登录账号 A（卖家）/ B（买家），按真实用户操作点击完整链路，关键步骤直连数据库断言 | Playwright + 系统 Edge + mysql CLI |
| 部署与接口验证 | 28 | 全部请求经 Nginx 反向代理，验证代理链路、静态资源策略、WebSocket 协议升级、缓存与限流、数据完整性 | Python HTTP + WebSocket + SQL |
| 单元测试（纯函数） | 31 | 对分类索引与编号规则做边界、异常与缺省形态断言 | Node（自研断言） |
| 后台管理端到端 | 集成在其中 | 管理员登录 → 商品审核 → 前台可见性验证 → 数据清理 | Playwright + SQL |
| 静态质量检查 | 4 类 | 设计令牌纪律 / 状态完备性 / 可访问性 / 前后端版本一致性 | 自研检查器（已接入 CI） |

### 1.2 用例覆盖分组（端到端 31 条）

| 分组 | 条数 | 覆盖内容 |
| --- | ---: | --- |
| 一、主业务闭环 | 20 | 注册、登录、资料与头像、发布商品、首页可见、收藏、私聊与已读、下单、买卖双方订单视图、状态流转、取消订单与商品释放 |
| 二、权限越权 | 6 | 未登录拦截、越权上下架他人商品、第三方查看他人订单、收藏/购买自己商品、给自己发私信 |
| 四、异常场景 | 5 | 空表单拦截、不存在资源、非法/超大文件、并发收藏、并发抢购防一物多卖 |

### 1.3 测试原则

1. **双账号隔离**：A/B 分别在不同浏览器上下文登录，localStorage 互不可见，杜绝"自买自卖"导致用例失效。
2. **断言不只看界面**：关键用例直连数据库校验（订单状态与买卖双方、金额、商品状态、未读消息数、静态资源缓存头等）。
3. **可重复执行**：用例启动前清理限流计数与前置数据，结束前校验演示数据不变量（用户 4 / 商品 17 / 收藏 4 / 订单 4 / 消息 9），保证不污染环境。
4. **测试对象是部署形态**：前端经 Nginx 8081 访问、后端以 prod 配置运行，而非本地开发态。

## 五、测试结论与遗留问题

### 5.1 结论

1. **功能正确性**：主业务闭环（发布 → 审核 → 检索 → 沟通 → 下单 → 交付）在真实部署形态下可完整跑通。
2. **安全与权限**：越权场景全部被正确拦截；生产配置下数据库详情探针关闭、限流对本机同样生效。
3. **界面质量**：三态（空/错/载）完备、对比度全部达标、键盘可达、窄屏无横向溢出。
4. **可重复性**：三套测试可反复执行且不污染演示数据；CI 对质量指标实行"阈值只许下降"的棘轮约束。

### 5.2 遗留问题（已知且已记录，非缺陷遗漏）

| 项 | 说明 |
| --- | --- |
| 后台窄屏适配 | 管理后台侧栏固定 210px，390px 下横向溢出。**经评估不做**：项目定位是电脑为主，后台为管理员在电脑上使用的功能；若后续需要，做法是把侧栏折成抽屉（与前台顶栏同一套交互） |
| 骨架屏未全覆盖 | 11/20；剩余为图表页（骨架收益低）与表单页（已有错误态兜底） |
| 浏览器兼容性 | 自动化用例仅在 Chromium 内核（Edge）上执行，未覆盖 Firefox/Safari |
| 安全测试 | 仅覆盖越权与鉴权类场景，未做渗透测试与依赖漏洞扫描 |
| 性能测试 | 有缓存与限流的压测记录（见 `docs/缓存与限流说明.md`），但未做正式的全链路性能测试 |
