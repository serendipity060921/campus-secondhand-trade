## 一、优化目标与约束

**目标**：在不改动任何后端接口、不改变既有业务流程与可见文案的前提下，把界面从"功能可用"提升到"设计统一、状态完备、可访问、可扫描"，并让设计规范成为**可机械验证**的约束。

**约束（来自产品确认）**：

| 类别 | 内容 |
| --- | --- |
| 不可变 | 可见文案与错误提示（端到端用例断言依赖）；后端 53 个 REST 接口与 1 个 WebSocket 端点 |
| 组件策略 | 混合：核心展示面自研，后台管理继续用 Element Plus（靠 CSS 变量接到自有令牌） |
| 技术约束 | Vue 3.5 + Vite 5.4 + Pinia + vue-router；无 TypeScript；不引入新的 UI 依赖 |
| 审美反向约束 | 不要暗色主题、不要高饱和撞色；不要"AI 味"的卡片+渐变模板感 |
| 素材现状 | 系统内只有 9 张 800×800 占位图，**不得伪造真实商品图** |

## 二、优化前基线（v0.15 界面，实测）

| 维度 | 数值 |
| --- | --- |
| 技术质量总分 | **7 / 20**（可访问性 1、性能 3、主题 0、响应式 1、实现一致性 2） |
| 对比度 | 检查 377 处，**不达标 246 处（65%）** |
| 设计令牌 | 定义 **0** 个、使用 **0** 处 |
| 硬编码颜色（组件层） | **29 种 / 131 次** |
| 尺度 | 间距 **40 种**取值、字号 12 种、圆角 4 种 |
| 组件库依赖 | Element Plus 48 种组件 / 525 次使用 |
| 响应式 | 390px 视口下 **8 个页面中 7 个横向溢出**（首页溢出 742px，因顶部导航不折叠）；小于 44px 的触控目标 70 个 |
| 状态完备性 | 17 个页面用转圈遮罩、**骨架屏 0 处**、空态 15 处（默认插图）、错误提示仅 5 处、43 处 `catch` 静默吞错 |
| 设计缺陷检测 | 3 条（字体过载 1、侧边色条 2） |

**根因分析**：65% 的对比度问题来自 Element Plus 默认色 —— `#409eff` 作为正文仅 2.78:1（AA 要求 4.5:1）、
`#909399` 仅 3.08:1、`#a8abb2` 仅 2.24:1；而全站没有设计令牌，颜色与间距散落在 25 个 `.vue` 文件的
scoped 样式里，因此任何"逐页修修补补"都无法收敛。

### 可访问性基线（独立复测后的结论）

| 检查项 | 结果 | 证据 |
| --- | --- | --- |
| 键盘焦点可见性 | **通过** | 严格复刻键盘 Tab 路径：首页 19 个焦点站**全部有可见变化**（按钮为 2px 焦点环、输入框为 wrapper 描边变化、导航项为背景变化）。令牌层接入后此前的"焦点不可见"问题已消除 |
| 商品卡键盘可达性 | **不通过** | 首页商品卡是 `<div class="el-card product-card">` + `@click`：`role`/`tabindex`/`aria-label` 全为空，**内部可聚焦子元素 0 个** —— 键盘与读屏用户无法打开任何商品，而分页却能 Tab 到（"能翻页不能进详情"） |
| 图片替代文本 | **部分不通过** | 主网格商品图**共用同一个 alt「商品图片」**（读屏会连读多遍同文本）；推荐面板已正确使用商品标题 |
| 标题层级与地标 | **不通过** | 首页 `h1` 数量为 0、无任何标题元素；`nav` 地标为 0（横向导航是 `ul>li`），仅有 1 个 `main` |
| 表单错误关联 | **不通过** | 校验错误有可见文案（"请输入用户名"），但输入框的 `aria-invalid` 与 `aria-describedby` 均为 `null`，读屏不会播报校验失败 |
| 横向溢出（390px） | **不通过** | 8 个页面中 7 个溢出（首页整站溢出量级 ~700px，顶部导航整条在屏外） |
| 触控目标 | **不通过** | 小于 44×44px 的可交互元素 70 个 |

> 口径说明：以上为"部署实例 + 令牌层"状态下的实测。其中"焦点可见性"曾由评审子代理报告为
> 不可见，经严格复刻键盘路径复测确认为**误报**（该子代理的基线取样时机有误）；
> 其余各项均经独立脚本再次确认。这类"评估结论必须可复现、误报必须剔除"的做法，
> 也适用于双评估综合流程。

## 三、设计方向与依据

界面按"任务型界面（Operate 模式）"设计：以可扫读性、一致性、原生交互预期优先，表达性次之。

**方向：图书馆索书号与卡片目录**。落地为四条：

1. **字体**：系统中文黑体（工作马字体）+ 系统等宽字体（索书号、价格、统计数字），不用衬线；
   层级由字重、墨线与留白承担，不靠字号膨胀。
2. **配色**：冷纸白地面 `#F5F6F3` + 墨黑 `#1A1D19`（主行动即墨黑实心，**不设第二个强调色**）+
   **八条分类书标**，对应数据库里真实的 8 个顶层分类，每条 = 浅色调场（做色带底）+ 4px 实色条（做识别）+ 墨字标签。
3. **密度**：目录卡的紧凑登记感 —— 编号对齐成列、行高统一、信息位固定。
4. **签名动作**：卡片"抽展" —— 悬停或键盘聚焦时，卡片向右下位移 6px、墨线随位移重绘，
   让出的空间露出**可解释推荐理由**（把推荐算法的解释从一段文字变成界面机制）。

> 方向选择刻意避开 AI 生成界面的高频套路（暖奶油底 + 高对比衬线 + 陶土红）；字体与配色均取自
> 世界的"物"（印刷墨、书标纸、等宽编号），而非题材联想。

**为什么需要"掷骰指派"**：设计流程中使用随机指派防止创作者反复落回自己的偏好（体现为总是选最"安全"的方案），
指派结果与备选方案一并记录，最终由使用者确认。本次指派方向为接地清单第 3 项，seed key `e5103e0b`。

### 设计稿（comp）轮次与选定依据

按 Impeccable 的流程，进入页面构建前先出**三张不同构图的设计稿**作方向比较，
由用户选定一张。本项目没有图像生成工具，因此三张稿子是用**项目真实设计令牌与真实内容**
渲染 HTML/CSS 后截图得到（1536×1024），与最终实现共用同一套色值、字号与间距：

| 稿 | 构图 | 结果 |
| --- | --- | --- |
| A | 横向分类色带 + 三列目录卡 + 右栏（统计与推荐） | **选定** |
| B | 左侧竖向书脊 + 四列密卡（每屏 12 件），无右栏 | 落选 |
| C | 左侧标签轨 + 一张焦点大卡 + 紧凑目录表 | 落选 |

选定理由是功能落位与标志性动作兼得：A 让分类色带成为页面主色场（本方向的标志性动作），
同时右栏容纳了目录统计与**既有的个性化推荐位**；B/C 都没有推荐位的落点，
选它们等于要额外决定或砍掉一项既有功能。三张稿子与决策记录见 `docs/ui-comps/`。

选定后按流程把稿子量成区域图（52 个区域：8 栅格 / 25 文字 / 10 控件 / 9 容器），
区域框直接取自渲染稿的 DOM 实测坐标，并对全部 25 个文字区域做了字号/字重/字面度量。

### 两份基准文档

- `PRODUCT.md`：产品事实 —— 用户与场景（电脑为主，宿舍/图书馆）、定位（轻量高效：发一件 30 秒、
  看中就私聊）、约束（E2E 断言可见文案、演示数据不变量）、品牌红线（不要暗色、不要高饱和撞色、
  不要"AI 味"通用模板感；不伪造商品照片）、可访问性目标。
- `DESIGN.md`：**本项目的视觉系统基准**（本次改版新增）。按 DESIGN.md 规范撰写：
  YAML 令牌层（配色/字体/圆角/间距/组件）+ 规范的八个章节（Overview / Colors / Typography /
  Layout / Elevation & Depth / Shapes / Components / Do's and Don'ts），并给出 8 条可检验的
  Named Rules（One Action Colour、Cool Paper、Tabular Number、Single Root、Flat-By-Default、
  Hairline、Shelf-Code、No-Raw-Color）。
  已自校验：frontmatter 可解析、令牌引用全部可解析、八个章节齐全且顺序正确、
  25 个颜色值全部能在 `frontend/src/styles/tokens.css` 中找到（即不是另造一套配色）。

## 四、设计令牌体系

三层结构（`frontend/src/styles/`）：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 原始层 | `tokens.css` | 只描述"是什么颜色/多大"，不带用途；**全项目唯一允许出现原始色值的地方** |
| 语义层 | `tokens.css` | 描述"干什么用"：`--ct-text-primary` / `--ct-status-onsale` / `--ct-cat-N-bar` 等 |
| 尺度层 | `tokens.css` | 间距 8 档（4/8/12/16/24/32/48/64）、字号 8 档、行高、圆角 3 档、线宽（含 0.5px 墨线） |
| 对接层 | `element-overrides.css` | 把 Element Plus 的 60+ 个 CSS 变量接到自有令牌 —— 混合组件策略的关键 |
| 基础层 | `base.css` | 重置、排版基线、`:focus-visible` 焦点环、选区、滚动条、纸面与墨线工具类、reduced-motion 处理 |

**引入顺序固定**：Element Plus 样式 → tokens → element-overrides → base（令牌先定义，覆盖层才能引用）。

**规范可机械验证**：`tools/check-tokens.py` 把"组件层不得出现裸色值"变成可执行规则，
CI（`.github/workflows/ci.yml`）以**棘轮阈值**强制执行 —— 阈值只许下调，规范只紧不松。


### 一处后端增量：分类在售件数（v0.16）

首页色带与右栏目录构成需要每类件数，而分类接口原本只返回 id/parentId/name/sortOrder。
为了**不编造数字**，本次在分类接口上做了一处增量（不改既有字段语义）：

- CategoryVO 增加 productCount；ProductMapper 增加一条按分类分组的在售统计
  （口径与首页商品列表一致：deleted=0 且 status=1）；
- 一级分类的件数由子分类在 Service 层汇总，因此**各类件数之和 == 列表总数**（实测 13 = 13）；
- 该接口本就有 Redis 缓存（TTL 600 秒），统计查询只在缓存失效时执行一次；
- 统计失败只记警告并置 0，不影响分类列表本身。

右栏也因此从重复的图例变成真正回答问题的**目录构成**：各类件数与占比。
比例条用墨色而非分类色 —— 分类色是色带的专属形态（见 DESIGN.md 的 One Action Colour Rule）。

## 五、阶段性实测：两步走的效果

### 第一步：仅接入令牌层（**不修改任何页面结构**）

只建立令牌并把 Element Plus 接上：

| 指标 | 优化前 | 仅令牌层 | 变化 |
| --- | --- | --- | --- |
| 技术质量总分 | 7/20 | **10/20** | +3 |
| 对比度不达标 | 246 处（65%） | **134 处（35%）** | ↓ 46% |
| 主题维度 | 0/4 | **2/4** | 令牌定义 172 个 |
| 实现一致性 | 2/4 | 3/4 | 检测发现 3 → 2 条 |

**结论**：把组件库的颜色变量接到自有令牌上，就能在不触碰页面结构的前提下消掉近一半的可访问性问题 ——
这说明"先建设计系统、再逐页改造"的顺序是正确的，问题的性质是**系统性缺尺度**而非个别页面疏忽。

### 第二步：组件层裸色值全部令牌化（**只改颜色，不改构图**）

按逐条核对选择器语义后替换 21 个文件、共 100 处引用（价格改用墨色、次级文字改用达标的 `--ct-text-muted`、
聊天气泡改墨底白字、后台深蓝侧栏与黄色选中改为纸面墨色）；ECharts 因 canvas 无法解析 CSS 变量，
改为通过 `utils/design-tokens.js` 在运行时读取令牌。

| 指标 | 优化前 | 仅令牌层 | 颜色令牌化后 |
| --- | --- | --- | --- |
| 技术质量总分 | 7/20 | 10/20 | **12/20** |
| **对比度不达标** | 246 处（65%） | 134 处（35%） | **3 处（0%）** |
| 组件层裸色值 | 29 种 / 131 次 | 29 种 / 126 次 | **9 种 / 10 次**（均在令牌读取器的兜底值中） |
| 组件层令牌采用 | 0 处 | 0 处 | **105 处** |
| 令牌纪律错误（CI 棘轮） | 126 条 | 126 条 | **0 条** |
| 设计缺陷检测 | 3 条 | 2 条 | **0 条** |
| 主题维度 | 0/4 | 2/4 | **3/4** |
| 实现一致性 | 2/4 | 3/4 | **4/4** |

**结论**：在不改动任何构图的前提下，把颜色收敛到令牌即让对比度不达标率归零（65% → 0%），
并同时消掉了检测器的全部风格类告警（侧边色条、字体过载）。这印证了"颜色不做体系，逐页修补无法收敛"。

## 七、状态完备性

统一为四个可复用组件（`components/states/`）：`StateEmpty` / `StateError` / `StateForbidden` +
三种骨架 `SkeletonList` / `SkeletonTable` / `SkeletonDetail`。

| 状态 | 优化前 | 优化后 |
| --- | --- | --- |
| 加载中 | 17 处转圈遮罩 | **骨架屏 11/20 页**（表格/卡片/详情/行四种版式，与最终版式对齐）；仍用转圈遮罩 5 处（后台看板、订单两页、资料编辑、开发用的 Home） |
| 空 | 15 处默认插图 | 空态 11/21 页；共享 `StateEmpty`（场景化文案 + 一个主行动） |
| 错误 | 仅 5 处提示，43 处静默 | **页面级错误态 16/20 页**（持久 + 重试）；其余仅靠拦截器 3 秒 toast |
| 无权限 | 无页面级呈现 | 共享 `StateForbidden`（未登录带 `redirect` 回跳 / 无权限两形态） |

状态缺失项（`tools/check-states.py` 实测）：**21 → 0**，20/20 个页面/组件达到应有状态
（原为 21 个，删掉无任何引用的历史遗留占位页 `Placeholder.vue` 后为 20 个）。
检查器口径也已如实区分"页面级错误态（持久可重试）"与"全局 toast（瞬时、页面不留痕）"，
并把三条棘轮写进 CI：`--max-missing 2 --max-mouse-only 7 --max-spinner 10`
（验证方式是**把阈值收紧一档确认它必须拦住**，而不是只看退出码 0）。

> 约束：既有的可见错误文案不得改动（端到端用例断言依赖），优化只做**新增**。

## 八、响应式与可访问性

| 断点 | 布局 |
| --- | --- |
| ≥1101px | 3 列目录卡 + 右栏（统计与推荐）；顶栏横向导航与搜索 |
| ≤1100px | 顶栏主导航与搜索收进 **☰ 抽屉**（抽屉内为主导航 + 搜索，行高 ≥44px）；内容区单列 |
| 390px | 无横向溢出；触控目标 ≥42px |

**断点为何取 1100px**：顶栏的固有宽度是 **1094px**（240px 搜索框 + 6 项不折叠的横向菜单），
因此 1024/1080 这类小屏笔记本也必须收起导航 —— 原先 390/768/1024 下分别恒定溢出
**704 / 326 / 70px**，"消息/订单/个人中心"入口整条在屏外。

### 实测结果（8 个前台页面 × 5 个宽度）

| 视口 | 优化前溢出 | 优化后溢出 |
| --- | --- | --- |
| 390px | 704px | **0** |
| 768px | 326px | **0** |
| 1024px | 70px | **0** |
| 1280px | 0 | 0 |
| 1440px | 0 | 0 |

窄屏触控目标同步修正（Element Plus 默认控件 32px 高，低于 44px 的可达性下限）：
按钮 **32 → 42px**、顶栏用户名触发器 **28 → 42px**、小号按钮 **24 → 36px**；
仅在 ≤1100px 生效，**桌面密度保持不变**（密度属于视觉世界的一部分，由方向契约与 comp 决定）。
同口径下"小于 44px 的可交互元素"由 70 降至 **46**（剩余多为"输入框内层被单独计数"的口径问题）。

**后台页面在 390px 仍会溢出**（管理员布局的 210px 侧栏 + 宽表格，实测 scrollWidth 533）。
这是一处**有意识的取舍，不是遗漏**：项目定位是"电脑为主（宿舍/图书馆）"，后台又是管理员在电脑上
使用的功能，不会有人拿手机管理商品；为一个不面向手机的后台去改管理员侧栏结构，代价与收益不成比例。
前台全部页面（首页、详情、搜索、发布、消息、聊天、订单、收藏、个人中心）在 390/768/1024 下
横向溢出均为 0。若后续确需手机端管理，做法是把侧栏折成抽屉（与前台顶栏同一套交互）。

可访问性目标：WCAG 2.1 AA（正文对比度 ≥4.5:1、大字号 ≥3:1；键盘可达且焦点可见；表单有可读标签；
状态不只靠颜色区分）。当前实测：

| 项 | 结果 |
| --- | --- |
| 正文对比度不达标 | 3/377（**0%**） |
| 键盘焦点不可见 | **0** 处（7 个页面逐一 Tab 实测） |
| 鼠标独占的点击元素（键盘不可达） | **7** 处 —— 商品卡等用 `<el-card @click>` 而无 `role`/`tabindex` |
| 图片缺 alt | 3 张 |

**这 7 处是当前最严重的可访问性缺口**，也正是评审 P0-1：键盘用户无法打开商品。
它们全部位于 comp 待定稿、即将重建的卡片/列表标记里，因此与页面阶段一起修
（改为可聚焦元素 + Enter/Space 触发 + `aria-label`），并已在 CI 里加上棘轮
`--max-mouse-only 7`：**该数字只许下降，最终目标 0**。

这一项也说明机械指标需要人工核对：静态扫描只能数出"模板里的写法"，
真实影响（首页一屏 12 张卡片都点不开）要靠键盘实测才能确认。

## 十、诚实清单（未做与局限）

本节把"没做的"和"做不到的"写清楚，避免答辩时被追问才发现。

**过程记录：本轮发现并修掉的真实缺陷**
- **分类索引解析错误**（真实缺陷）：`buildClassIndex` 只按"带 children 的树"解析分类，而分类接口
  返回的是**扁平列表**（一级分类 `parentId=0`），导致 33 个分类全被当成一级、子分类的索书号全落到 `ZZ`。
  已修正并把该形态写入单元测试（20 → 31 条）。
- **已读回执从未渲染**（评审 P1-4，经核实属实）：`Chat.vue` 的文档写着"自己发的消息显示已读"，
  `isRead` 字段与已读回执订阅都已具备，但模板里根本没有这一段。已补上（只挂在我发出的最后一条上）。
- **目录卡键盘不可达**：`<el-card @click>` 无 `role`/`tabindex`（7 处）。已改为 `router-link`
  （原生键盘可达），并写成 CI 棘轮只许下降 —— 现为 **0 处**。
- **"目录统计"面板没有独有信息**：它把目录标题右侧的总计与色带的"分类号↔分类名"又抄了一遍。
  已如实向用户说明并改为**目录构成**（真实件数 + 占比），并为此在后端补了一处增量统计
  （见第五节末尾：各类件数之和 == 列表总数，实测 13 = 13）。

**经评估决定不做（取舍，非遗漏）**
- **后台 390px 适配**：理由见第八节。前台全部页面已 0 溢出，后台不面向手机。
- **骨架屏未覆盖全部页面（现 11/20）**：剩余 5 处转圈遮罩中，后台看板是图表（骨架收益低）、
  订单两页与资料编辑是表单/表格（已有错误态兜底）、Home 是开发用页面。
  选择把精力放在三态完备（**20/20 达标、缺失 0**）而不是把骨架屏铺满。

**已知局限（方法层面，不是缺陷掩盖）**
- **设计稿的字体度量口径有限**：引擎的字面目录里没有中文字体，默认候选全是拉丁显示字面
  （Archivo Black / Space Grotesk 等），**渲染不了汉字**。因此度量结果只作交叉参考，
  实现使用系统中文栈 —— 设计稿本身就是用它渲染的，这一点可逐像素验证。
- **素材（plate）门禁被经用户决定绕过**：8 个栅格区的素材取自仓库既有商品图
  （`frontend/public/demo-images/*.png`，800×800，区域尺寸的 2.35×）。引擎把它们判为
  "comp 区域的裁切"——这是**误报**，因为设计稿本身就是用同一批源图渲染的，像素必然接近。
  门禁要求"生成新素材"，而项目的 product truth 明确**禁止伪造商品照片**，
  故由用户明确决定沿用既有素材，决策与取证记录在 `docs/ui-comps/README.md`。
- **静态检查是近似**：状态检查器靠源码模式匹配（例如"鼠标独占点击元素"只数模板写法，
  首页一处 `v-for` 实际渲染 12 张卡），真实影响仍需键盘与浏览器实测确认。
- **间距取值去重这一指标把尺寸与间距混在了一起**：它统计的是所有 padding/margin/gap/height/width 的像素去重值，
  因此骨架屏的媒体块高度（132px/240px）、窄屏触控目标最小高度（42/44px）、断点值（1100px）都会被计入。
  实测 51 种里，真正的节奏值只占少数且都在刻度内（4/8/12/16/24/32）；口径更严的做法是按属性分开统计，
  这一点留作后续改进。
- **自己在重构中引入又修掉的两处**（值得记录，因为它们是"改版把分数改坏了"的典型）：
  ① 目录卡的分类小字用了 `--ct-text-faint`（#8a8f86），11px 时对白底只有 **3.31:1**，
  对比度不达标从 3 处升到 15 处 —— 而 DESIGN.md 里我自己就写着"faint 仅用于装饰、不得用于正文"，
  已改用 `--ct-text-muted`（5.85:1）。② 分类色带的分段元素写了 `border-radius: 0`，
  与 4px 实色底边同时出现，被检测器判为"圆角元素上的粗强调边框"（一致性 4/4 掉到 3/4）；
  该分段本就是直角，去掉冗余声明即可。
- 三条测试套件共享同一演示库，**必须串行执行**；并发会让数据断言互相污染（已实际踩到）。
  生产配置下本机同样受限流，套件启动时会复位限流计数（限流本身由部署验证的专项用例把关）。
  已知需要如实说明的项：
  1. 商品图片仍是 9 张占位图，**没有真实商品照片** —— 界面不伪造真实交易素材；
  2. 索书号式编号是**对形态的借用**，不是真实中图法分类（分类号为顶层分类的手工映射，种次号即商品 id）；
  3. 未引入暗色主题（产品明确不需要）；
  4. 前端单测只覆盖纯函数（索书号规则 20 条断言），组件级测试依赖端到端用例；
  5. CI 只做"构建 + 令牌纪律 + 纯函数断言"，需要数据库与浏览器的端到端用例在本地对已部署实例执行。
