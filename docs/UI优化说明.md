# UI 优化说明（v0.16 全站前端改版）

> 本文是毕业论文「UI 优化」一节的成稿基础，所有数字都由 `tools/` 下的脚本机械产出、可复现，
> 原始证据保存在 `.impeccable/review/<档位>/`（截图 + manifest + audit.json + inventory.json + detect.json + tokens-lint.json）。
>
> **数据可复现**（在同一部署实例上运行）：
> ```bash
> python tools/capture-ui.py --label <档位>     # 17 页 × 桌面1440/移动390 = 34 张截图 + 溯源清单
> python tools/ui-inventory.py --label <档位>   # 颜色/间距/字号/圆角去重数、令牌用量、组件库依赖、样式债
> python tools/ui-audit.py --label <档位>       # 对比度、焦点、触控、溢出、DOM、特效 + 五维度 0-4 分
> python tools/check-tokens.py --label <档位>   # 组件层裸色值/!important/越档取值清单
> node tests/unit/catalogue.test.mjs            # 索书号编号规则的纯函数断言（20 条）
> ```

## 一、优化目标与约束

**目标**：在不改动任何后端接口、不改变既有业务流程与可见文案的前提下，把界面从"功能可用"提升到"设计统一、状态完备、可访问、可扫描"，并让设计规范成为**可机械验证**的约束。

**约束（来自产品确认）**：

| 类别 | 内容 |
| --- | --- |
| 不可变 | 可见文案与错误提示（端到端用例断言依赖）；后端 53 个 REST 接口与 1 个 WebSocket 端点 |
| 组件策略 | 混合：核心展示面自研，后台管理继续用 Element Plus（靠 CSS 变量接到自有令牌） |
| 技术约束 | Vue 3.5 + Vite 5.4 + Pinia + vue-router；无 TypeScript；不引入新的 UI 依赖 |
| 审美反向约束 | 不要暗色主题、不要高饱和撞色；不要"AI 味"的卡片+渐变模板感 |
| 素材现状 | 系统内只有 9 张 800×800 占位图，**不得伪造真实商品图** |

## 二、优化前基线（v0.15 界面，实测）

| 维度 | 数值 |
| --- | --- |
| 技术质量总分 | **7 / 20**（可访问性 1、性能 3、主题 0、响应式 1、实现一致性 2） |
| 对比度 | 检查 377 处，**不达标 246 处（65%）** |
| 设计令牌 | 定义 **0** 个、使用 **0** 处 |
| 硬编码颜色（组件层） | **29 种 / 131 次** |
| 尺度 | 间距 **40 种**取值、字号 12 种、圆角 4 种 |
| 组件库依赖 | Element Plus 48 种组件 / 525 次使用 |
| 响应式 | 390px 视口下 **8 个页面中 7 个横向溢出**（首页溢出 742px，因顶部导航不折叠）；小于 44px 的触控目标 70 个 |
| 状态完备性 | 17 个页面用转圈遮罩、**骨架屏 0 处**、空态 15 处（默认插图）、错误提示仅 5 处、43 处 `catch` 静默吞错 |
| 设计缺陷检测 | 3 条（字体过载 1、侧边色条 2） |

**根因分析**：65% 的对比度问题来自 Element Plus 默认色 —— `#409eff` 作为正文仅 2.78:1（AA 要求 4.5:1）、
`#909399` 仅 3.08:1、`#a8abb2` 仅 2.24:1；而全站没有设计令牌，颜色与间距散落在 25 个 `.vue` 文件的
scoped 样式里，因此任何"逐页修修补补"都无法收敛。

## 三、设计方向与依据

界面按"任务型界面（Operate 模式）"设计：以可扫读性、一致性、原生交互预期优先，表达性次之。

**方向：图书馆索书号与卡片目录**。落地为四条：

1. **字体**：系统中文黑体（工作马字体）+ 系统等宽字体（索书号、价格、统计数字），不用衬线；
   层级由字重、墨线与留白承担，不靠字号膨胀。
2. **配色**：冷纸白地面 `#F5F6F3` + 墨黑 `#1A1D19`（主行动即墨黑实心，**不设第二个强调色**）+
   **八条分类书标**，对应数据库里真实的 8 个顶层分类，每条 = 浅色调场（做色带底）+ 4px 实色条（做识别）+ 墨字标签。
3. **密度**：目录卡的紧凑登记感 —— 编号对齐成列、行高统一、信息位固定。
4. **签名动作**：卡片"抽展" —— 悬停或键盘聚焦时，卡片向右下位移 6px、墨线随位移重绘，
   让出的空间露出**可解释推荐理由**（把推荐算法的解释从一段文字变成界面机制）。

> 方向选择刻意避开 AI 生成界面的高频套路（暖奶油底 + 高对比衬线 + 陶土红）；字体与配色均取自
> 世界的"物"（印刷墨、书标纸、等宽编号），而非题材联想。

**为什么需要"掷骰指派"**：设计流程中使用随机指派防止创作者反复落回自己的偏好（体现为总是选最"安全"的方案），
指派结果与备选方案一并记录，最终由使用者确认。本次指派方向为接地清单第 3 项，seed key `e5103e0b`。

## 四、设计令牌体系

三层结构（`frontend/src/styles/`）：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 原始层 | `tokens.css` | 只描述"是什么颜色/多大"，不带用途；**全项目唯一允许出现原始色值的地方** |
| 语义层 | `tokens.css` | 描述"干什么用"：`--ct-text-primary` / `--ct-status-onsale` / `--ct-cat-N-bar` 等 |
| 尺度层 | `tokens.css` | 间距 8 档（4/8/12/16/24/32/48/64）、字号 8 档、行高、圆角 3 档、线宽（含 0.5px 墨线） |
| 对接层 | `element-overrides.css` | 把 Element Plus 的 60+ 个 CSS 变量接到自有令牌 —— 混合组件策略的关键 |
| 基础层 | `base.css` | 重置、排版基线、`:focus-visible` 焦点环、选区、滚动条、纸面与墨线工具类、reduced-motion 处理 |

**引入顺序固定**：Element Plus 样式 → tokens → element-overrides → base（令牌先定义，覆盖层才能引用）。

**规范可机械验证**：`tools/check-tokens.py` 把"组件层不得出现裸色值"变成可执行规则，
CI（`.github/workflows/ci.yml`）以**棘轮阈值**强制执行 —— 阈值只许下调，规范只紧不松。

## 五、阶段性实测：仅接入令牌层的效果

**不修改任何页面结构**，只建立令牌并把 Element Plus 接上：

| 指标 | 优化前 | 仅令牌层 | 变化 |
| --- | --- | --- | --- |
| 技术质量总分 | 7/20 | **10/20** | +3 |
| 对比度不达标 | 246 处（65%） | **134 处（35%）** | ↓ 46% |
| 主题维度 | 0/4 | **2/4** | 令牌定义 172 个 |
| 实现一致性 | 2/4 | 3/4 | 检测发现 3 → 2 条 |

**结论**：把组件库的颜色变量接到自有令牌上，就能在不触碰页面结构的前提下消掉近一半的可访问性问题 ——
这说明"先建设计系统、再逐页改造"的顺序是正确的，也说明问题的性质是**系统性缺尺度**而非个别页面疏忽。

## 八、响应式与可访问性

| 断点 | 布局 |
| --- | --- |
| ≥1280px | 3 列目录卡 + 右栏（统计与推荐） |
| 1024–1279px | 3 列，右栏折到列表下方 |
| 768–1023px | 2 列，分类色带横向可滚动 |
| <768px | 1 列；导航收进抽屉；触控目标 ≥44px |

可访问性目标：WCAG 2.1 AA（正文对比度 ≥4.5:1、大字号 ≥3:1；键盘可达且焦点可见；表单有可读标签；
状态不只靠颜色区分 —— 在售/交易中/已售出用"空框/半填/实心划线"的形态编码）。
最终判定见下节数据：**对比度不达标比例【待填】**、**焦点不可见元素【待填】**、**小于 44px 的触控目标【待填】**。

## 十、诚实清单（未做与局限）

- 【待填】本节的目的是把"没做的"和"做不到的"写清楚，避免答辩时被追问才发现。
  已知需要如实说明的项：
  1. 商品图片仍是 9 张占位图，**没有真实商品照片** —— 界面不伪造真实交易素材；
  2. 索书号式编号是**对形态的借用**，不是真实中图法分类（分类号为顶层分类的手工映射，种次号即商品 id）；
  3. 未引入暗色主题（产品明确不需要）；
  4. 前端单测只覆盖纯函数（索书号规则 20 条断言），组件级测试依赖端到端用例；
  5. CI 只做"构建 + 令牌纪律 + 纯函数断言"，需要数据库与浏览器的端到端用例在本地对已部署实例执行。
