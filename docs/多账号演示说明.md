# 多账号演示说明（同一浏览器两个窗口登不同账号）

> 一句话结论：**同一浏览器所有标签页共享登录态，这是标准行为，不是缺陷。**
> 想同时登两个账号，用「无痕窗口 / 另一个浏览器 / 另一个浏览器配置文件」即可。

## 一、为什么会这样

前端把登录凭证存在 `localStorage`（`frontend/src/utils/auth.js`）：

```js
const TOKEN_KEY = 'campus_trade_token'
localStorage.setItem(TOKEN_KEY, token)      // 登录时写入
localStorage.getItem(TOKEN_KEY)             // 每次请求读取
```

`localStorage` 的作用域是 **源（origin）= 协议 + 域名 + 端口**，
所以在 `http://127.0.0.1:8081` 下打开的**所有标签页与窗口共用同一份**：

| 存储 | 作用域 | 结果 |
| --- | --- | --- |
| `localStorage` | 同一浏览器 + 同一源 + **所有标签页** | A 标签页登录 → B 标签页也是同一账号 ✓ 正常 |
| `sessionStorage` | 同一浏览器 + 同一源 + **单个标签页** | 每个标签页独立（但新开标签页要重新登录） |
| Cookie | 同上（可设 `SameSite`） | 同上 |

这也是 GitHub / 淘宝 / 学校教务系统的行为：**你在一个标签页登录，另一个标签页不用再登**。
它正是用户故事 **US-USER-02「登录与登录态保持」AC1** 的实现方式 ——
如果改成"每个标签页独立"，那条故事的"保持登录"就不成立了。

## 二、想同时登两个账号（演示买卖双方）：三种办法

| 办法 | 操作 | 适合 |
| --- | --- | --- |
| **① 无痕窗口**（推荐） | Edge 按 `Ctrl+Shift+N`（Chrome 是 `Ctrl+Shift+N`）→ 在新窗口登录另一个账号 | 临时演示，30 秒搞定 |
| **② 换一个浏览器** | Edge 登买家、Chrome 登卖家 | 需要长期并排对照 |
| **③ 浏览器多配置文件** | Edge：右上角头像 → 「添加个人资料」→ 新配置文件独立登录 | 长期开发/答辩 |
| ④ 自动化测试里怎么做 | Playwright `browser.new_context()` 每账号一个 context，天然隔离 | 写测试用（现有套件已这样） |

## 三、要不要改成"每个标签页独立登录"

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| 保持现状（推荐） | `localStorage` | 无。符合用户预期与 US-USER-02 |
| 每标签页独立 | 改用 `sessionStorage` | ① 新开标签页必须重新登录；② 刷新才保留；③ 与"登录态保持"故事冲突 |
| 同一浏览器多账号并存 | 用「账号切换器」把多个 token 存数组 + 顶栏下拉切换 | 工作量大（前端 + 拦截器 + 故事/AC/测试全要改），收益低 |

**建议保持现状。** 若导师明确要求"同浏览器多账号并存"，再按第三种方案排期。

## 四、演示时的推荐组合

```
窗口 A（普通）    admin / 123456        管理员：审核、用户管理、举报处理
窗口 B（无痕）    stu_test01 / abc12345 买家：下单、评价（订单 1 已完成）
窗口 C（另一浏览器）stu_demo / 123456    卖家：卖出商品、待交易订单
```

三步演示"一笔交易的两端"：
1. 窗口 B 下单 → 窗口 C 刷新「我卖出的」看到新订单
2. 窗口 C 点「标记待交付」→ 窗口 B 看「我买到的」状态变化
3. 窗口 B 确认收货 → 商品变「已售出」→ 窗口 B 评价 → 窗口 A 后台看信用分

## 补充：为什么你可能记得「以前能同时登两个账号」

我查了 git 历史：`frontend/src/utils/auth.js` **从 v0.03 建脚手架起只有一个提交**，
全程用 `localStorage`，**从未用过 `sessionStorage`** —— 也就是说"以前能"并不是因为代码不同。

最可能的原因是：**当时那两个窗口不是同一个"源"**。

| 窗口 | 地址 | 是否同一个源 |
| --- | --- | --- |
| Vite 开发服务器 | `http://127.0.0.1:5173` | ❌ 端口不同 → **不同源** |
| Nginx 部署形态 | `http://127.0.0.1:8081` | ❌ 同上 |

`localStorage` 按 **源（协议 + 域名 + 端口）** 隔离，端口不同就是两个独立的存储空间。
所以早期开发时"5173 一个账号 + 8081 一个账号，还能互相发消息"是**完全成立的** ——
两个窗口各自持有一份 token，而后端是同一个（8080）与同一个库，消息自然互通。

想复现这个效果（仅调试用）：

```powershell
cd frontend; pnpm dev      # 起 5173
# 窗口 A: http://127.0.0.1:5173  登录 stu_test01
# 窗口 B: http://127.0.0.1:8081  登录 stu_demo
```

> 答辩现场不建议这么用（dev server 依赖 HMR 与代理，容易出状况）；
> 现场用**无痕窗口**登两个账号更稳。
