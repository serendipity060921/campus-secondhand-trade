### 20.2 权限：前后端双层校验

| 层 | 实现 | 验证 |
| --- | --- | --- |
| 前端 | 路由 `meta.requiresAdmin`，守卫校验 `userInfo.role === 1`，非管理员提示并跳回首页 | 学生登录后访问 `/admin/dashboard` 被拦回 `/home` |
| 后端 | `AdminController` 类级别 `@LoginRequired(admin = true)`，拦截器统一校验 | 未登录 5 个后台接口全部 **401**；学生 Token 全部 **403**；管理员 **200** |

### 20.3 数据看板（ECharts 6 按需引入）

| 区域 | 内容 |
| --- | --- |
| 概览卡片 | 用户总数、商品总数（含在售）、订单总数（含已完成）、累计成交额（含近 7 天）、待审核商品数、待处理举报数 |
| 增长与交易 | 近 7 天趋势：新增用户/新增商品/新增订单（折线）+ 成交额（柱状，双 Y 轴） |
| 结构分布 | 商品分类分布（饼图）、订单状态分布、商品状态分布（环形图） |
| 其他 | 私信总数、收藏总数、在售占比、订单完成率 |

**指标口径**：成交额只统计 `status=3`（已完成）订单；"今日新增"按 `create_time >= 今日 0 点`；
趋势缺失日期补 0 保证折线连续（详见设计文档第 3 节）。

### 20.4 商品审核与流程开关

- 审核通过 → `status=1` 上架并写 `shelf_time`；驳回 → `status=2` 并记录 `audit_remark`（卖家可见原因）；
- 同时写入 `auditor_id` / `audit_time`，并调用 v0.12 的 `CacheEvictor` 让列表/详情/推荐缓存立即失效；
- 非 `待审核` 商品再次审核返回 **8003**，避免误改已售出商品状态；
- **审核开关** `campus.audit.enabled`：默认 `false`（发布即上架，兼容 v0.05 以来的流程与既有测试）；
  设为 `true` 时新发布商品进入「待审核」，形成"发布 → 待审核 → 审核通过 → 上架"完整闭环。

### 20.5 举报与用户管理

| 功能 | 要点 |
| --- | --- |
| 提交举报 | 商品详情页「举报商品」；原因四选一（虚假信息/违禁物品/辱骂骚扰/其他）+ 补充说明；不能举报自己的内容（8006）、对象不存在（8007） |
| 处理举报 | 处理（`status=1`）/ 忽略（`status=2`），填写处理结果，记录处理人与时间；重复处理返回 8002 |
| 用户管理 | 列表附带发布商品数、成交订单数、被举报数；禁用后登录返回 **2004「账号已被禁用」**；管理员不能禁用自己（8004），不能禁用其它管理员 |
| 操作日志 | `AUDIT_PRODUCT` / `OFFLINE_PRODUCT` / `DISABLE_USER` / `ENABLE_USER` / `HANDLE_REPORT`，含操作人、对象、详情、IP、时间 |
