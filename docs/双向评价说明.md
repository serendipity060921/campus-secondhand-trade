# 双向评价（v0.18 / 第6批-㉑）

> 一句话说明：为已完成订单引入**买卖双方互评**——买家可以评价卖家，卖家也可以评价买家，
> 每笔订单每人只评一次；评分联动信用分，且匿名只隐藏展示身份。

- 数据表：`evaluation`（`db/schema/06-evaluation.sql`）
- 接口：`/api/evaluation/**`（6 个）
- 单测：`EvaluationModuleServiceImplTest`（25 条）
- 业务码段：**9xxx**（沿用项目"按模块分段"的约定）

---

## 一、为什么做这个功能

平台原本只有**举报**（负向）机制，缺少正向反馈，带来三个实际问题：

| 问题 | 后果 |
| --- | --- |
| 买家无法判断卖家是否靠谱 | 信用分是注册时给的固定值，之后从不变化，等于没有 |
| 卖家无法筛选买家 | 放鸽子、拖付款的买家在卖家之间没有口碑 |
| 商品详情页没有评价 | "二手交易"最需要的**信任成本**没有被降低 |

## 二、表设计：四个刻意的决定

```sql
UNIQUE KEY uk_order_from (order_id, from_user_id)   -- 同一订单每人只能评一次
role       TINYINT   -- 1 买家评卖家 / 2 卖家评买家
to_user_id BIGINT    -- 冗余：查"我收到的评价"不必关联订单
product_id BIGINT    -- 冗余：商品详情页展示评价，避免三表关联
```

| 决定 | 理由 |
| --- | --- |
| `uk_order_from` 唯一索引 | 并发重复提交只成功一次；与收藏、注册同一套兜底思路 |
| `role` 显式落库 | 不靠 `fromUserId` 与买卖双方比对反推——订单字段一变就全错 |
| `to_user_id` / `product_id` 冗余 | 把"按人查""按商品查"从三表关联降为单表查询 |
| **不建外键** | 评价是**行为留痕**：订单/商品被逻辑删除后评价仍应可查；同时避免灌库顺序带来的外键顺序问题（CI 从零建库因此安全） |

## 三、规则（每条都有单测固定）

| # | 规则 | 违反时的业务码 |
| --- | :-: | --- |
| 1 | 只有**买卖双方**能评，且评价对象由订单推导（前端只能传 `orderId`） | `9002` |
| 2 | 只有**已完成（status=3）**的订单能评 | `9003` |
| 3 | 同一订单每人**只能评一次**（先查再插 + 唯一索引兜底） | `9004` |
| 4 | 评分必须 1~5 星 | `400`（`@Min/@Max`）或 `9005` |
| 5 | 内容 ≤ 500 字 | `400` 或 `9006` |
| 6 | 被评价人必须存在 | `9007` |
| 7 | 订单不存在 | `9001` |

★ 规则 1 是**安全边界**：如果允许前端传 `toUserId`，任何人都可以把"差评"挂到任意用户身上。
所以 DTO 里**只有** `orderId`，被评价人由 `buyerId`/`sellerId` 推导。

## 四、信用分联动（有边界，防刷）

| 评分 | 信用分变化 |
| :-: | :-: |
| 4~5 星 | **+1** |
| 3 星 | 0 |
| 1~2 星 | **−1** |

实现细节：

```sql
UPDATE user
SET credit_score = LEAST(GREATEST(COALESCE(credit_score, 100) + (delta), 0), 150)
WHERE id = ?
```

- **不用"先读后写"**：`credit = credit + 1` 在并发下会丢更新，这里由数据库做原子更新；
- **夹在 [0, 150]**：一次差评不会把账号"打死"，一次好评也不会无限刷分；
- 唯一索引保证**每单只加减一次** —— 刷分的唯一办法是刷真实完成的订单，成本很高。

## 五、匿名

`anonymous=1` 时：昵称改成"匿名同学"、头像清空，
但 **`fromUserId` 仍然保留** —— 管理端与本人（"我发出的评价"）仍需可追溯。

这是刻意的分层：**展示层匿名 ≠ 数据层匿名**。若数据层也抹掉，一旦出现恶意评价就无法追责。

## 六、接口清单

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/evaluation` | 需登录 + 限流 20/300s | 提交评价 |
| GET | `/api/evaluation/product/{productId}` | 公开 | 商品的评价列表 |
| GET | `/api/evaluation/received/{userId}` | 公开 | 某人收到的评价 |
| GET | `/api/evaluation/mine` | 需登录 | 我发出的评价 |
| GET | `/api/evaluation/summary/product/{productId}` | 公开 | 平均分 / 好评率 / 星级分布 |
| GET | `/api/evaluation/order/{orderId}` | 需登录（仅买卖双方） | 判断"我评过没有" |

读接口公开是刻意的：新用户看不到任何口碑，双向评价就失去意义。
